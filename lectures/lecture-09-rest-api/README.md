# Lab 9 REST API ინტეგრაცია

საერთო retry მექანიზმი გამოიყენება WeatherClient, AirQualityClient და CurrencyClient კლასებში. HTTP მოთხოვნა და სტატუსის შემოწმება ცალკე `_get()` მეთოდშია; JSON პასუხი მუშავდება მოთხოვნის წარმატებით დასრულების შემდეგ.

## გაშვება

პროექტის ძირეული საქაღალდიდან:

```bash
python lectures/lecture-09-rest-api/multi_source_fetch.py
python lectures/lecture-09-rest-api/retry_live_demo.py
python lectures/lecture-09-rest-api/retry_demo.py
```

პირველი სკრიპტი რეალურად ითხოვს ამინდს, ჰაერის ხარისხსა და NBG-ის კურსს. თითოეულს დამოუკიდებელი შეცდომის დამუშავება აქვს; ერთი წყაროს ჩავარდნა დანარჩენებს არ აჩერებს. ნებისმიერი წყაროს ჩავარდნისას გასვლის კოდია 1.

მეორე სკრიპტი ხელოვნურად ქმნის ქსელის ჩავარდნებს, თუმცა რეალურად ელოდება 1 და 2 წამს. მის მიერ დაბეჭდილი დაბინძურების მნიშვნელობები სატესტოა. ამოწმებს როგორც მესამე მცდელობაზე წარმატებას, ასევე ყველა მცდელობის ამოწურვას.

მესამე სკრიპტი რვა ავტომატურ ტესტს ასრულებს. იქ HTTP პასუხები და sleep ჩანაცვლებულია mock-ებით: მოწმდება ცდების რაოდენობა და მოთხოვნილი დაყოვნებები, ლოდინის გარეშე.

## Retry და AI Corner

მაქსიმუმ სამი მცდელობა ნიშნავს საწყის მოთხოვნას და ორ განმეორებას. დაყოვნებებია 1 და 2 წამი. 4 წამიანი ლოდინი მხოლოდ მეოთხე მცდელობის დამატების შემთხვევაში იქნებოდა. `max_delay` ზღუდავს ზრდას, `functools.wraps` ინარჩუნებს ფუნქციის სახელსა და აღწერას.

ხელახლა ვცდით timeout-ს, კავშირის შეცდომას (SSL შეცდომის გარდა) და HTTP 408, 429, 500, 502, 503, 504 პასუხებს. HTTP 400, 401, 403 და 404 დაუყოვნებლივ ბრუნდება შეცდომად. არასწორი JSON ან მონაცემის სტრუქტურა არ მეორდება. ყველა HTTPError-ის ერთნაირად გამეორებას ამიტომ დავუმატეთ `should_retry` პირობა.

ეს სასწავლო პოლიტიკაა. 429-ისთვის Retry-After სათაურის პატივისცემა და ერთდროული კლიენტებისთვის jitter დამატებითი გაუმჯობესებებია; მოცემული კოდი მათ არ ახორციელებს. ConnectionError ყოველთვის დროებით პრობლემას არ ნიშნავს, თუმცა მცდელობები მკაცრად შეზღუდულია.

## tenacity ალტერნატივა

`tenacity_example.py` იყენებს იმავე შერჩევის ფუნქციას, სამ მცდელობასა და exponential backoff-ს. `reraise=True` ბოლო თავდაპირველ exception-ს ინარჩუნებს, რათა კლიენტმა ის საკუთარ APIError-ად გარდაქმნას. ამ პარამეტრის გარეშე საბოლოო შეცდომა ჩვეულებრივ RetryError იქნება. ალტერნატივა ტესტით მოწმდება; ძირითადი კლიენტები საკუთარ დეკორატორს იყენებენ.

NBG-ის `rate` შეესაბამება `quantity` ერთეულს. ერთი ერთეულის კურსისთვის ვიყენებთ `rate / quantity`-ს. პასუხში დაბეჭდილია წყაროს თარიღიც; ის მოთხოვნის დღით არ იცვლება. ჰაერის მონაცემები მოდელირებულია და მათი დრო UTC-შია. წყაროები ერთ გაშვებაში იკითხება, მაგრამ მათი დროითი პერიოდები განსხვავდება.
